# 08. Тестирование

Цель: при обновлениях проверять, что уже сделанное работает. Основная проверка — модульные тесты доменной логики. UI-тесты закрывают короткий набор сквозных сценариев.

## Модульные тесты

| ID | Требование | Приоритет |
|---|---|---|
| TST-11 | Доменная логика покрыта модульными тестами: окно заполнения и граница дня, значение дня из чек-инов, правила аналитики (раздел 15), синхронизация блоков с текстом (FR-04.11), миграции БД, экспорт и импорт. | Must |
| TST-12 | Текущее время в логике берётся через `TimeProvider` (.NET), в тестах подменяется. | Must |
| TST-13 | Границы окна проверяются на значениях 03:59, 04:00, 17:59, 18:00 и при смене таймзоны. | Must |

## UI-тесты

| ID | Требование | Приоритет |
|---|---|---|
| TST-01 | Сценарии из таблицы ниже покрыты UI-тестами, которые запускаются автоматически. | Should |
| TST-02 | Тесты работают с приложением как с чёрным ящиком: через элементы интерфейса. Исключение — тестовые параметры запуска (TST-06). | Must |
| TST-03 | Элементы интерфейса имеют стабильные идентификаторы (AutomationId), которые не меняются при смене текста и стилей. | Must |
| TST-05 | Тесты используют отдельную тестовую базу. Реальная база пользователя не затрагивается. | Must |
| TST-06 | Отладочная сборка принимает параметры запуска: подменённое время и путь к тестовой базе с данными. В релизной сборке параметры игнорируются. | Must |
| TST-07 | Тесты запускаются на Android-эмуляторе и не требуют ручных действий. | Must |
| TST-08 | Перед слиянием в main запускаются модульные тесты, упавший тест блокирует слияние. UI-тесты запускаются вручную перед релизом. | Should |
| TST-09 | Отчёт о прогоне UI-тестов сохраняется: какие сценарии прошли, какие упали, скриншоты при падении. | Should |
| TST-10 | UI-тесты не проверяют цвета, точные отступы и тексты советов. Проверяются наличие элементов и результат действия. | Should |

## Сценарии UI-тестов

| Сценарий | Связанное требование |
|---|---|
| Запуск в 18:00 открывает мастер | FR-01.1 |
| Запуск в 03:59 открывает мастер за предыдущий день | FR-01.1, FR-01.7 |
| Запуск в 04:00 открывает календарь | FR-01.2 |
| Без выбора обеих шкал «Продолжить» и «Сохранить» неактивны | FR-03.2 |
| «Сохранить» на карточке 1, итоговый экран, запись видна в календаре | FR-03.6, FR-03.9, FR-05.2 |
| Нажатие блока добавляет подпись в поле | FR-04.3 |
| «✕» в мастере создаёт черновик | FR-03.18, FR-01.6 |
| Отчёт открывается после итогового экрана | FR-01.5, FR-06.6 |

Инструмент для UI-тестов: Appium с драйвером UiAutomator2. Окончательно выбирается при разработке.
